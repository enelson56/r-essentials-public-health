9  Summary Tables

Creating Table 1 with gtsummary

DESCRIPTIVES · GTSUMMARY · GROUP COMPARISONS

Tell the Story in a Table

A well-designed table helps readers understand a dataset before they examine more complex results. Build descriptive summaries with gtsummary, compare groups, and make your tables easier to interpret.

NoteLearning objectives

By the end of this lesson, you should be able to:

  1. Create summary tables using gtsummary.
  2. Describe continuous and categorical variables.
  3. Compare groups within a dataset.
  4. Make a polished table suitable for a report or manuscript.

9.1 Why do we create summary tables?

Summarizing data is one of our first steps in dealing with data. Recall that we always want to summarize by WHO, WHAT, WHEN, and WHERE so we can work towards the HOW and WHY. This material is meant to help you rapidly summarize your data.

We often call this process “Creating Table 1.” The idea is that the first table in a manuscript or presentation often describes our study population. Who participated? What characteristics did they have? Were the groups similar or different?

There are several packages that do this well (tableone, finalfit, table1, compareGroups to name a few). One of my favorites is gtsummary, which helps us create publication-ready summary tables with relatively little code. We will start simple and then build up to something more sophisticated.

9.2 Get to know the data

We will use trial, an example dataset included with the gtsummary package. It contains simulated data on 200 patients in a clinical trial. Each row represents a patient, and the columns describe patient characteristics, treatment, and outcomes.

NoteNo download needed

trial is simulated teaching data, not actual patient records. Once you have installed gtsummary, the dataset is available without importing a file.

# install.packages("gtsummary")  # Run once if needed

library(gtsummary)

#---Save the example data as an object
#---recall that gtsummary:: states to explicity call trial from that package

9.5 Stratified tables: Compare groups

We can also make stratified tables, which means the summary is shown separately for each group. This is especially useful for a Table 1 with these clinical trial data, where we might want to compare patient characteristics across treatments. But the same application works for comparing across other groups (i.e., biological sex, race/ethnicity, regions, etc.)

Just add by = VariableName within tbl_summary().

#---Stratified summary by treatment group
patients %>%

9.6 Make the table easier to read

9.6.0.1 Changing text labels (rows)

We can replace R variable names with more informative labels. This is particularly helpful when preparing a table for readers who haven’t seen our code.

The syntax is label = list(variable ~ "New Label", ...). Notice the tilde (~), which separates the original variable from the label you want displayed.

#---More informative row labels
patients %>%
  tbl_summary(
    by = trt,
    include = c(age, grade, stage, marker, response),
    label = list(
      age ~ "Age (years)",
      grade ~ "Tumor Grade",
      stage ~ "Tumor Stage",
      marker ~ "Marker Measurement",
      response ~ "Tumor Response"))

9.7 Add p-values to a stratified table

Wait, gtsummary can also run statistical tests for me? Genius!

Once we have a table stratified by a group, we can add add_p() to compare those groups. By default, gtsummary typically uses the Wilcoxon rank-sum test for continuous variables and a chi-square or Fisher’s exact test for categorical variables with two groups. The precise choice depends on the variable type and the data.

#---Add p-values to a treatment-group table
patients %>%
  tbl_summary(
    by = trt,
    include = c(age, grade, stage, marker)) %>%
  add_p()

9.7.1 Specify a test when needed

For example, if we specifically want a t-test for age, we can tell gtsummary which test to use. This is an option, not something we should apply blindly to every variable.

#---Request a t-test for age
patients %>%
  tbl_summary(by = trt, include = c(age)) %>%
  add_p(test = list(age ~ "t.test"))

9.8 Control how variables are summarized

9.8.1 Continuous variables

By default, gtsummary often displays continuous variables as median (25th percentile, 75th percentile). But for some assignments or manuscripts, we may want mean (standard deviation) instead. We can adjust the statistic presented in the table using statistic = within the tbl_summary().

#---Show mean and standard deviation
patients %>%
  tbl_summary(
    by = trt,
    include = c(age, marker),
    statistic = all_continuous() ~ "{mean} ({sd})",
    digits = all_continuous() ~ 1)
Characteristic Drug A
N = 981		 Drug B
N = 1021
Age 47.0 (14.7) 47.4 (14.0)
    Unknown 7 4
Marker Level (ng/mL) 1.0 (0.9) 0.8 (0.8)
    Unknown 6 4
1 Mean (SD)
TipRead this as…

“Create a table of age and marker by treatment group, summarize continuous variables using the mean and standard deviation, and round those summaries to one decimal place.”

9.8.2 Force a variable to be continuous

Sometimes a numeric variable with only a few distinct values is treated as categorical. If we truly intend to summarize it numerically, we can use type = to specify that. The example is intentionally simple; age is already continuous here. The point is to learn where the type argument belongs.

#---Explicitly request a continuous summary for age
patients %>%
  tbl_summary(
    include = c(age, marker),
    type = list(age ~ "continuous") )
Characteristic N = 2001
Age 47 (38, 57)
    Unknown 11
Marker Level (ng/mL) 0.64 (0.22, 1.41)
    Unknown 10
1 Median (Q1, Q3)

9.8.3 Binary variables and categorical display

response and death are binary variables. Depending on how a binary variable is encoded, gtsummary may show only one level by default.

#---Compare default and full categorical display
patients %>%
  tbl_summary(include = c(response, death))
Characteristic N = 2001
Tumor Response 61 (32%)
    Unknown 7
Patient Died 112 (56%)
1 n (%)

If you want both categories displayed, specify "categorical" as the variable type.

patients %>%
  tbl_summary(
    include = c(response, death),
    type = list(c(response, death) ~ "categorical"))
Characteristic N = 2001
Tumor Response
    0 132 (68%)
    1 61 (32%)
    Unknown 7
Patient Died
    0 88 (44%)
    1 112 (56%)
1 n (%)
NoteWhy might this matter?

A one-row binary summary can be compact and useful (for example, the percentage who responded). Showing both levels can be clearer for some audiences to interpret the tables.

9.9 Additional options for polished tables

Once you are comfortable with tbl_summary(), there are several additional functions worth knowing. You don’t have to memorize all of them today. Think of this section as a reference you can return to.

Options inside tbl_summary():

  • digits = all_continuous() ~ 2 — change decimal places.
  • missing_text = "Missing" — change the label for missing data.
  • statistic = all_continuous() ~ "{mean} ({sd})" — show mean and standard deviation.
  • type = list(variable ~ "categorical") — control how a variable is displayed.

Functions added afterward using %>%:

  • add_overall() — add an overall column.
  • add_n() — add a column showing nonmissing sample sizes.
  • add_p() — add statistical comparisons.
  • add_ci() — add confidence intervals for supported summaries.
  • bold_labels() / italicize_labels() — style variable labels.
  • bold_levels() / italicize_levels() — style category labels.
  • modify_caption("**Title**") — add a table caption.
  • modify_header() — change column headings.
  • modify_spanning_header() — place a header across columns.
  • bold_p(t = 0.05) — bold p-values below the chosen threshold.
NoteA helpful habit

Build your table one step at a time. Run tbl_summary() first, then add one formatting function, and check the output. That makes troubleshooting much easier than writing a long pipeline all at once.

9.10 The Whole Enchilada — Carl Hanson

Now let’s put many of these options together. This example is intentionally longer: you are not expected to memorize it. The goal is to recognize how each step adds something useful to the final table.

#---The Whole Enchilada: a polished clinical trial Table 1
patients %>%
  select(trt, age, grade, stage, marker, response) %>%
  tbl_summary(
    by = trt,
    label = list(
      age ~ "Age (years)",
      grade ~ "Tumor Grade",
      stage ~ "Tumor Stage",
