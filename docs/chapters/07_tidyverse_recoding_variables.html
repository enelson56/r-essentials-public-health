7  Factors: Recoding Variables

Dealing with Categorical Data

FACTORS · CATEGORIES · RECODING

Turn Values into Meaning

A useful analysis often starts by making variables easier to interpret. Practice creating categories, recoding responses, renaming factor levels, and putting categories in a meaningful order.

NoteLearning objectives

By the end of this lesson, you should be able to:

  1. Understand how factors work in R.
  2. Create a binary variable from a numeric variable using if_else().
  3. Create several categories from a numeric variable using case_when().
  4. Convert a variable into a factor using factor().
  5. Rename factor levels using fct_recode().
  6. Put factor levels in a specific order using fct_relevel().

7.1 Factors in R

A factor is how R represents categorical data. Examples include education level, satisfaction ratings, or categories such as low, medium, and high. When working with categorical variables, we often need to rename categories, combine them, or put them in a meaningful order. Fortunately, the tidyverse makes this relatively easy!

Factors have levels: the possible categories of a variable. R stores factors using underlying integer codes (starting at 1), but displays their category names. The order of the levels matters, especially when making tables and graphs.

7.4 Situation 1: Create a Binary Variable

Sometimes we want to take a continuous (numeric) variable and create two groups. We can do this with if_else(): when the condition is true, R uses the first value; otherwise, it uses the second.

  • Let’s create a variable identifying diamonds that cost less than $1,000.
#---Create a new binary variable
diamonds_data <- diamonds_data %>%
  mutate(price_group = if_else(price < 1000,
                               "Under $1,000",
                               "$1,000 or more"))

#---Check our work
diamonds_data %>%
  count(price_group)
# A tibble: 2 × 2
  price_group        n
  <chr>          <int>
1 $1,000 or more 39441
2 Under $1,000   14499
class(diamonds_data$price_group)
[1] "character"
TipRead this as…

“Take diamonds_data, create a new variable called price_group, and label each diamond Under $1,000 if its price is less than 1,000. Otherwise, label it $1,000 or more.”

With if_else(), read the three arguments as condition, value if TRUE, value if FALSE.

This creates a character variable with two categories. If we want it to be a factor, we can use factor() and specify the order.

diamonds_data <- diamonds_data %>%
  mutate(price_group = factor(price_group,
                              levels = c("Under $1,000", "$1,000 or more")))

class(diamonds_data$price_group)
[1] "factor"
levels(diamonds_data$price_group)
[1] "Under $1,000"   "$1,000 or more"
  • Quick check: What would you change if you wanted the cutoff to be $2,000 instead?

7.5 Situation 2: Create Several Categories

What if we want more than two groups? The case_when() function allows us to define multiple conditions.

case_when() is a function from the dplyr package that allows you to create or recode variables based on multiple conditions.

Think of it as an expanded version of if_else(). Instead of choosing between two outcomes, you can specify several conditions and assign different values to each.

How it works:

  1. R evaluates each condition from top to bottom.
  2. The first condition that evaluates to TRUE determines the assigned value.
  3. The ~ separates the condition (left) from the assigned value (right).
  4. .default specifies what happens when none of the conditions are met.

Important: The order of conditions matters! R uses the first matching condition, even if subsequent conditions are also true.

Let’s group diamonds by their price.

diamonds_data <- diamonds_data %>%
  mutate(price_category = case_when(
    price < 1000 ~ "Under $1,000",
    price < 5000 ~ "$1,000–$4,999",
    TRUE ~ "$5,000 or more"))

#---Check our work
diamonds_data %>%
  count(price_category)
# A tibble: 3 × 2
  price_category     n
  <chr>          <int>
1 $1,000–$4,999  24714
2 $5,000 or more 14727
3 Under $1,000   14499
TipRead this as…

“Take diamonds_data and create price_category. If the price is under $1,000, use the first label. Otherwise, if it is under $5,000, use the second label. Give all remaining diamonds the third label.”

Read each ~ as “then assign”. R uses the first matching condition.

R evaluates the conditions in order. If a diamond costs $3,000, it fails the first condition but meets the second. TRUE ~ catches everything that did not match an earlier condition. Here, every diamond has a price, so all observations receive a category.

Notice that price_category is a character variable. We will learn how to order categories next.

Quick check: Why don’t we need to write price >= 1000 & price < 5000 for the second category?

7.6 Situation 3: Rename Factor Levels

Sometimes the categories in our data are correct, but their names could be clearer. We can use fct_recode() to rename factor levels without changing which observations belong to each category.

This function follows the same naming convention as rename(), which you may have used to rename variables: new_name = old_name.

Let’s rename two levels of the original cut variable.

#---Rename selected factor levels
diamonds_data <- diamonds_data %>%
  mutate(cut_renamed = fct_recode(cut,
                                 "Excellent" = "Ideal",
                                 "Average" = "Good"))
#---Check our Work
#---Before
levels(diamonds_data$cut)
[1] "Fair"      "Good"      "Very Good" "Premium"   "Ideal"    
#---After
levels(diamonds_data$cut_renamed)
[1] "Fair"      "Average"   "Very Good" "Premium"   "Excellent"
TipRead this as…

“Take the existing cut factor and create cut_renamed. Change the label Ideal to Excellent and Good to Average, leaving the other categories alone.”

Remember: fct_recode() uses new label = old label, just like rename().

Notice that we only needed to specify the levels we wanted to rename. The other levels remain unchanged, and their original ordering is preserved.

Quick check: How would you change "Fair" to "Basic" as well?

7.7 Situation 4: Put Factor Levels in the Correct Order

This is one of the most common situations, so pay attention! R doesn’t always know the order that makes sense to us. It will load in factors variables alphabetically by default when loading an Excel file or CSV.

The fct_relevel() function lets us choose the order of factor levels. Let’s put our new price categories in order from least to most expensive.

diamonds_data <- diamonds_data %>%
  mutate(price_category = fct_relevel(
    factor(price_category),
    "Under $1,000",
    "$1,000–$4,999",
    "$5,000 or more"))

#---Check our work
diamonds_data %>%
  count(price_category)
# A tibble: 3 × 2
  price_category     n
  <fct>          <int>
1 Under $1,000   14499
2 $1,000–$4,999  24714
3 $5,000 or more 14727
TipRead this as…

“Convert price_category to a factor, then arrange its levels in the order Under $1,000, $1,000–$4,999, and $5,000 or more.”

fct_relevel() changes the order of categories, not their names or which diamonds belong to them.

The order is determined by the sequence we specify, from first to last. We used factor() because case_when() created a character variable, not a factor. If you have a factor that you are releveling, you do not need to call the factor() function.

Quick check: What would happen if you listed “$5,000 or more” first?

7.8 Situation 5: Combine Factor Levels

Sometimes a variable has more categories than we need. The fct_collapse() function lets us combine existing factor levels into broader groups.

The original cut variable has five levels. Let’s reduce it to three categories:

  • Lower: Fair and Good
  • Middle: Very Good
  • Higher: Premium and Ideal
diamonds_data <- diamonds_data %>%
  mutate(cut_group = fct_collapse(cut,
    "Lower" = c("Fair", "Good"),
    "Middle" = "Very Good",
    "Higher" = c("Premium", "Ideal")))

#---Check our work
diamonds_data %>%
  count(cut_group)
# A tibble: 3 × 2
  cut_group     n
  <ord>     <int>
1 Lower      6516
2 Middle    12082
3 Higher    35342
levels(diamonds_data$cut_group)
[1] "Lower"  "Middle" "Higher"
TipRead this as…

“Take the five original cut categories and combine them into three new groups: Lower, Middle, and Higher.”

In fct_collapse(), the name on the left of = is the new group; the names on the right are the original levels being combined.

Let’s explicitly put these groups in order, too.

diamonds_data <- diamonds_data %>%
  mutate(cut_group = fct_relevel(cut_group,
                                 "Lower", "Middle", "Higher"))

levels(diamonds_data$cut_group)
[1] "Lower"  "Middle" "Higher"

Quick check: If we wanted only two cut categories, which original levels would you combine? There is no single correct answer, but you should be able to explain your choice.

7.9 One Final Check

Whenever you recode a variable, check your work. At a minimum, look at the counts and, when working with factors, the order of the levels.

#---Compare the original and new categories
diamonds_data %>%
  count(cut, cut_group)
# A tibble: 5 × 3
  cut       cut_group     n
  <ord>     <ord>     <int>
1 Fair      Lower      1610
2 Good      Lower      4906
3 Very Good Middle    12082
4 Premium   Higher    13791
5 Ideal     Higher    21551
#---Check the levels
levels(diamonds_data$cut_group)
[1] "Lower"  "Middle" "Higher"
TipRead this as…

“Count diamonds for each combination of their original cut and new cut_group categories so we can verify that the recoding worked as intended.”

The original variable is still available, so we can compare it with the new one. This is one reason I like creating new variables instead of overwriting the originals.
