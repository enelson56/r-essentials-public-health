8  Missing Data in R

A practical R programming lesson

NA VALUES · COMPLETE CASES · FILTERING

Notice What Is Missing

Missing observations can change which records are included in an analysis. Learn how to identify NA values, recognize the consequences of complete-case filtering, and make deliberate choices about which data to retain.

NoteLearning objectives

By the end of this lesson, you should be able to:

  1. Understand how R represents missing values.
  2. Identify missing values in a dataset.
  3. Know the consequences of complete-case filtering.

8.1 Introduction to Missing Data

MISSING DATA. Missing data is a real pain. It can lead to serious issues in any statistical program, not just RStudio. The goal of this walkthrough is to show you how RStudio handles missing values and some common practices for addressing them.

RStudio has certain values reserved for special purposes. One is NA, meaning Not Available. It represents a missing value in a dataset. Another is NaN, meaning Not a Number, which can result from undefined calculations such as 0/0. We also have Inf and -Inf, which represent positive and negative infinity. Finally, NULL represents the absence of an object or value, rather than a missing observation within a regular data column.

We will focus primarily on NA in this tutorial. It is the special value you are most likely to encounter when working with real datasets. But be aware that the others exist!

8.2 A Dataset with Missing Values

We will use the built-in airquality dataset. It contains daily air-quality and weather measurements in New York from May through September 1973. It already has missing observations, so it gives us a realistic example without needing to download anything.

#---Load packages
library(tidyverse)

#---Create a working copy of the built-in data
air_data <- airquality

#---Look at the data
glimpse(air_data)

Columns: 6

8.2.2 Using anyNA() and is.na()

Another approach is to use sapply() with anyNA() or is.na(). sapply() applies a function to each column. anyNA() tells us whether a column contains any missing values, while is.na() identifies the individual missing observations.

#---Which variables contain at least one missing value?
sapply(air_data, anyNA)
  Ozone Solar.R    Wind    Temp   Month     Day 
   TRUE    TRUE   FALSE   FALSE   FALSE   FALSE 
#---How many values are missing in each variable?
sapply(air_data, function(x) sum(is.na(x)))
  Ozone Solar.R    Wind    Temp   Month     Day 
     37       7       0       0       0       0
TipRead this as…

“For every variable in air_data, check which values are missing using is.na(), then add up the TRUE values to count the missing observations.”

R treats TRUE as 1 and FALSE as 0 when calculating the sum.

We can also use a tidyverse approach to calculate missing counts:

#---Count missing observations in each column
air_data %>%
  summarise(across(everything(), ~ sum(is.na(.x))))
  Ozone Solar.R Wind Temp Month Day
1    37       7    0    0     0   0

8.3 But Why?!!!

So why does this matter? Well, R does not automatically ignore missing values in many calculations. It makes us acknowledge that the data are incomplete. Let’s see this in action.

#---Try to calculate an average with missing values
mean(air_data$Ozone)
[1] NA

R returns NA because some ozone measurements are missing. How can it calculate an average if it does not know all the values?

To tell R to calculate the mean using only the available observations, we can use na.rm = TRUE. The argument means remove missing values for this calculation.

#---Calculate the mean using available ozone measurements
mean(air_data$Ozone, na.rm = TRUE)
[1] 42.12931
TipRead this as…

“Calculate the average ozone measurement, leaving out observations where ozone is missing.”

Warning

Important: na.rm = TRUE does not prove that the data are missing at random. It simply excludes the missing values from this calculation. Whether that is an appropriate analysis depends on why values are missing.

8.4 Beware of Complete-Case Data

  • Take-home point: Be careful with na.omit()!

One thing many beginners discover through ChatGPT or a good old Google search is the na.omit() function. But please know what it does before you use it. It checks each row (observation) and removes the entire row if any variable contains NA. An observation might have almost everything available, but a single missing value is enough to remove it.

#---How many observations did we start with?
nrow(air_data)
[1] 153
#---DANGER: Keep only observations complete on every variable
air_complete <- air_data %>%
  na.omit()

#---How many observations remain?
nrow(air_complete)
[1] 111

Notice how many observations we lose. This is known as complete-case analysis. Sometimes it is appropriate, but we should never do it automatically without considering the consequences.

You may also encounter drop_na() from tidyr. With no variables specified, it has a similar effect: it removes rows containing missing values in any column.

#---Also removes rows with missing values in any column
air_complete2 <- air_data %>%
  drop_na()

nrow(air_complete2)
[1] 111
WarningWhy does this matter?

Dropping rows can reduce your sample size and may introduce bias if the observations with missing data differ systematically from those with complete data. Fewer missing values in your table does not automatically mean a better analysis.

8.5 A Concrete Example of Dealing with NA Values

Here is a situation you will encounter as you work with real data. Remember, data management—recoding variables, summarizing data, and dealing with missing values—is often the hardest part of analysis. If you can do this, the rest gets much easier!

8.5.1 Deal with Variables One by One

Let’s work with the variables Ozone and Solar.R. Both contain missing observations. First, we’ll look at how many values are available for each variable.

#---Focus on two variables
air_trim <- air_data %>%
  select(Ozone, Solar.R)

#---Count missing values separately
air_trim %>%
  summarise(across(everything(), ~ sum(is.na(.x))))
  Ozone Solar.R
1    37       7

Now suppose we only want to calculate the mean ozone level. We do not need to discard a row just because its solar radiation value is missing.

#---Use all observations with an available ozone value
air_trim %>%
  filter(!is.na(Ozone)) %>%
  summarise(mean_ozone = mean(Ozone), n = n())
  mean_ozone   n
1   42.12931 116
TipRead this as…

“Take air_trim, keep only observations where Ozone is not missing, and calculate the average ozone level and number of observations remaining.”

The ! symbol means NOT. So !is.na(Ozone) means ozone is not missing.

8.5.2 The Remedy: Filter Only What You Need

If your analysis needs both ozone and solar radiation, then you can require both values to be available. The & symbol means AND.

#---Keep rows where BOTH variables are observed
air_trim %>%
  filter(!is.na(Ozone) & !is.na(Solar.R)) %>%
  summarise(
    mean_ozone = mean(Ozone),
    mean_solar = mean(Solar.R),
    n = n())
  mean_ozone mean_solar   n
1    42.0991   184.8018 111

You can express the same requirement with drop_na() if you specify the variables:

#---Remove rows missing either of these TWO variables only
air_data %>%
  drop_na(Ozone, Solar.R) %>%
  summarise(n = n())
    n
1 111
Note

This is an important distinction: drop_na() without variable names checks every column; drop_na(Ozone, Solar.R) checks only those two columns.

8.6 Looking Ahead: Missing Data in Summary Tables

In our next lecture, we will use the gtsummary package to make professional descriptive tables. Those tables can display missing observations explicitly, which helps readers understand how much data are available.

Here is a short preview. Don’t worry about learning all of the gtsummary syntax just yet—we will cover that in the next lecture.

#---Preview: Report missing observations in a summary table
library(gtsummary)

air_trim %>%
  tbl_summary(missing = "always", missing_text = "Missing")
Characteristic N = 1531
Ozone 32 (18, 64)
    Missing 37
Solar.R 205 (115, 259)
    Missing 7
1 Median (Q1, Q3)

By default, tbl_summary() may label missing values as Unknown. The missing_text argument lets us change that label. Reporting missingness is usually more informative than silently deleting observations.

TipWhat should you remember?

Before excluding observations, ask: Which variable is missing? How many observations are affected? Why might the values be missing? And does my analysis really require those observations to be removed?
