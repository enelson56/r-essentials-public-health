5  Importing Data

Bringing your work to life

CSV · EXCEL · DATA FRAMES

Bring Your Data to the Table

Before you can analyze data, you need to bring it into R and make sure it arrived correctly. Practice importing common file formats, checking your new objects, and keeping files organized in an R Project.

NoteLearning objectives

By the end of this lesson, you should be able to:

  1. Bring data into R from CSV, Excel, and RData files.
  2. Inspect the imported data to make sure it loaded correctly.
  3. Assign a name to the imported data for later use.

5.1 Getting data into R

So far, we’ve worked with data that are already available in R. In the real world, you’ll usually have to bring your own data into RStudio. There are many ways to do this, but let’s keep things simple. We’ll practice importing three common file types: CSV, Excel, and RData.

By the end, you should be able to import a file, give the resulting data a name, and make sure it loaded correctly.

5.1.1 Before you start: your R Project

Open the R Project you’ve been using for class. Put these three files in the same project folder as this lecture: practice1.csv, practice1.xlsx, and practice1.RData. We will also use practice_categories.csv for a short example about factors.

When the files are in your project folder, you can refer to them by name rather than typing a long path. This is one reason we use R Projects!

TipA routine worth developing
  1. Open your R Project.
  2. Put your data files in the project folder.
  3. Import the data in your R script.
  4. Check the rows, columns, and variable types.
  5. Save your script so you can repeat the import later.

5.2 Two ways to import a file

5.2.1 Option 1: Use the RStudio menu

This is still one of my favorite ways to get started. RStudio can help you find the file and generate the import code.

For a CSV file, go to Environment → Import Dataset → From Text (base). Browse to practice1.csv, check the preview and column headings, and import it. If the dialog offers an option to convert strings to factors, turn it on for this exercise.

For an Excel file, go to Environment → Import Dataset → From Excel. Choose practice1.xlsx, check the preview, and import it. You may be prompted to install the readxl package first.

Important: After importing, look at the code RStudio generated in the Console. Copy that code into your R script. Clicking through menus is fine, but saved code makes your work repeatable.

NoteUsing Posit Cloud?

If you’re using RStudio through Posit Cloud, first upload the data files using the Files → Upload button. Then follow the same steps as above.

5.2.2 Option 2: Write the code yourself

Once your files are in the project folder, writing the code is often even faster.

5.3 Import a CSV file

CSV stands for comma-separated values. A CSV file is a simple text file containing rows and columns of data. We’ll use the base R function read.csv().

# Read the CSV and save it as an object named patients
patients <- read.csv("data/practice1.csv", stringsAsFactors = TRUE)

head(patients)
  patient_id age gender      bmi smoking exercise fruit veg cancer
1          1  61      0 20.79721       2        0     1   2      0
2          2  68      1 27.30000       0        0     0   1      0
3          3  62      1 22.18310       0        0     1   3      0
4          4  61      1 35.26846       2        0     2   4      0
5          5  58      1 22.67334       1        0     3   1      0
6          6  46      1 27.69035       1        0     0   2      1
TipRead this as…

“Find the file named practice1.csv, read it into R, convert eligible text columns to factors, and store the resulting data frame in an object called patients.”

Here, read.csv() is a base R function (from the utils package). You can also write utils::read.csv() to name its package explicitly.

stringsAsFactors = TRUE is worth remembering. It tells R to convert character (text) columns into factors when importing a CSV. This can be useful for categorical variables, such as treatment group or neighborhood. We’ll work with factors in more detail later. I highly encourage you to use the read.csv() function and NOT the read_csv() function from the readr package.

ImportantA small but important distinction

In practice1.csv, columns such as gender and smoking use numbers as codes. stringsAsFactors = TRUE does not automatically turn numeric columns into factors. We will learn how to handle coded categories in a later lecture.

To see a factor created from text, try this small practice file:

category_data <- read.csv("data/practice_categories.csv", stringsAsFactors = TRUE)

str(category_data)
'data.frame':   6 obs. of  3 variables:
 $ id   : int  1 2 3 4 5 6
 $ group: Factor w/ 2 levels "Control","Intervention": 1 2 1 2 1 2
 $ score: int  7 9 6 8 5 10

Notice that the group column is a factor, while the score column is numeric.

5.4 Import an Excel file

Excel workbooks (.xlsx or .xls) need a different function. We’ll use read_excel() from the readxl package.

Install the package once, if needed, by running this in the Console:

install.packages("readxl")

Then load the package and import the workbook:

library(readxl)

excel_patients <- read_excel("data/practice1.xlsx")
head(excel_patients)
# A tibble: 6 × 9
  patient_id   age gender   bmi smoking exercise fruit   veg cancer
       <dbl> <dbl>  <dbl> <dbl> <chr>      <dbl> <dbl> <dbl>  <dbl>
1          1    61      0  20.8 2              0     1     2      0
2          2    68      1  27.3 0              0     0     1      0
3          3    62      1  22.2 0              0     1     3      0
4          4    61      1  35.3 2              0     2     4      0
5          5    58      1  22.7 1              0     3     1      0
6          6    46      1  27.7 1              0     0     2      1
TipRead this as…

“Load the readxl package, read the Excel file named practice1.xlsx, and store the result in an object called excel_patients.”

One difference: read_excel() does not have a stringsAsFactors argument. We’ll learn more about converting columns to factors later. For now, focus on importing the data correctly.

If an Excel workbook has multiple sheets, you can specify one using sheet =, such as read_excel("data/practice1.xlsx", sheet = 1).

5.4.1 Data frames and tibbles: a quick comparison

You might notice that our CSV and Excel imports look a little different in the Console. That’s normal! A tibble is a modern type of data frame. Both organize data into rows and columns, and both work with the R functions we’ll use in this course.

Traditional data frame Tibble
Common import function read.csv() readxl::read_excel() or readr::read_csv()
Console display Can print the whole dataset Shows a shorter preview and column types
Works with dplyr Yes Yes

Let’s check the two objects we just imported:

class(patients)
[1] "data.frame"
class(excel_patients)
[1] "tbl_df"     "tbl"        "data.frame"

You’ll see "data.frame" for patients. For excel_patients, R reports "tbl_df", "tbl", and "data.frame"—a tibble is also a data frame.

TipRead this as…

“Both files contain rows and columns. The CSV import gave us a traditional data frame; the Excel import gave us a tibble. For now, we can work with either one.”

One more distinction: the object format does not determine whether a column is a factor. Our read.csv(..., stringsAsFactors = TRUE) setting converts eligible text columns to factors, while read_excel() and readr::read_csv() generally leave text columns as characters. We’ll explore these differences later.

5.5 Load an RData file

An .RData (or .rda) file stores one or more R objects. Unlike CSV and Excel imports, load() restores the original object names from the file. You do not normally assign the result of load() to a new data-frame object.

#---read in an RData file
load("data/practice1.RData")
TipRead this as…

“Open the RData file, restore the objects saved inside it.”

Look for the restored object in your Environment pane. These typically come in with the exact name of the .RData file. You can always assign a new name to it if you’d like.

p_data <- practice1

NoteWhat should you check?

Are the column names correct? Do you have the expected number of rows? Are measurements numeric? Are categorical variables represented the way you expected?

5.7 Saving an R object (brief introduction)

If you’ve created an object in R, you can save it to an .RData file and load it later.

# Save one object to a file
save(patients, file = "data/patients_saved.RData")

# Load it back later
load("data/patients_saved.RData")

You may also see save.image() used to save an entire workspace. I generally don’t recommend relying on saved workspaces. Saving your script and rerunning it is a much better habit.
